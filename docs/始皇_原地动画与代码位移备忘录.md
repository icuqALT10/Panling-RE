## 代码侧必须遵守

1. 只有服务端实体动作控制器拥有整体位置控制权。推进、侧移、后撤、起跳、登离龙和跨场移动，通过游戏实体移动、碰撞及挂载逻辑实现；客户端跟随实体位置同步。
2. 不再从动画 root 提取位移，不保留“消费后反向补偿模型”的方案；不使用旧 bbmodel/旧 animation 的根位移曲线来叠加移动。
3. 攻击结束或被打断时，只结束相应移动状态；实体保留实际到达的位置，不能写回出招起点。受阻时以真实碰撞结果为准，不能为追赶动画进度穿墙或瞬移。
4. 当前 `footstep_schedule` 仅表示抬脚到落脚的局部动作时间、左右脚和发力/回稳阶段，不是世界步距。实际速度、位移距离与落脚需要在游戏内一起校准；贯甲旧版 3.75 格是历史动画位移，不作为新要求。
5. OBB、剑光两银标、持牌点等世界坐标统一由实体变换乘当前骨骼变换得到，不再额外累加动画 root 平移。原有身体转向需与实体朝向协调，避免角度重复施加。
6. 登龙/下龙由代码决定离地、抵达挂点与落地位置；模型仅提供腿部收放和落地缓冲。卡牌离手后独立世界飞行的既定要求继续有效。

这些是后续运行时约定，本轮没有新增 Java 移动逻辑，也没有将新技能接入游戏。原地预览中的脚掌相对地面后扫属于待与实体推进合成的步法，不能仅凭原地预览声明游戏接地已验证。
