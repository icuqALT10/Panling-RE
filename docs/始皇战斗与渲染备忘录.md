这些都是动画阶段建议，尚未接入实际判伤。与上一版相比总时长已变化，未来代码不能继续使用旧的结束 tick 或旧伤害窗口。

动作一次播放，首尾回到绑定姿态，并与 idle 混合衔接。没有 root 位移；脚步由局部骨骼完成。代码侧若同时推进实体，会改变脚的接触结果，须结合攻击状态处理移动。

所有动画吸附值统一为 20 FPS（0.05 秒网格）。五式的主要关节使用有界 Bezier 曲线，关键姿态两侧速度切线连续；下肢和头部按新的父骨骼运动重新解算，再按曲线误差保留必要键。连续发力曲线版为 2,015 个关键帧；本次增加 42 个剑骨骼转刃键，五式合计 2,057 个，比最初 5,474 个减少约 62%，仍保留稀疏编辑结构。

Blockbench 原生验收使用 80 FPS 采样，共 497 个姿态；GIF 以 40 FPS 捕获。运行时 animation JSON 的变化轨道按原生插值以 80 FPS 采样为线性键，以保留 Bezier 运动，这些采样率不会改变 bbmodel 的 20 FPS 编辑吸附。原生采样中最大脚底下沉约 0.284 模型单位（约 0.018 方块），剑尖银色标记最低高于地面约 2.065 模型单位，剑本身的几何包围盒最低点约 0.978 模型单位；头部世界朝向补偿误差最大约 1.19°。实际坐标和检查结果记录在 verification.json，游戏内接地与控制器混合仍需接入后检查。

### 连贯性修正

上一版的顿感有三个来源：主要关节同步停在蓄力姿势，线性插值在关键姿态处改变速度，挥砍后的减速缺少衔接。此次让落脚承重与上身加力重叠，按髋腰 → 肩臂 → 肘腕传力，再沿原有挥砍方向减速收势。金、木、土的握腕角度也重新校准，避免新的发力相位把剑尖带到地面以下。身体、剑、剑鞘、牌、骨骼层级、UV 和材质没有改变。

同样以 80 FPS 原生采样对比金式 0.45 秒关键姿态两侧：旧版剑尖速度约 1,140 → 122 模型单位/秒；新版约 762 → 579 模型单位/秒，左右切线连续，降低了此处突然刹停的感觉。此为局部运动检查，不代表已经做游戏内验收。不要把全部轨道统一改为 Catmull–Rom；后续再改幅度或相位时，须重新检查支撑接触、头部父变换补偿以及剑尖完整路径。

### 剑刃方向修正

上一版遗漏了刃口朝向：水式横扫主要用剑面扫过，木式斜斩和火式上挑也有剑面迎向运动方向的阶段。本次只给五式增加 `sword` 的旋转轨道，围绕剑柄中心轴转刃，握持位置、剑的几何、其他骨骼轨道及 0.35 秒起斩时序保持原样。水式两次横扫采用相近的刃面方向，避免反向挥砍时无意义地翻转 180°；收势平滑回到原有绑定方向。

剑的未旋转 cube 坐标中，长轴为 -Y、两侧刃口为 ±X、宽剑面的法向为 ±Z。转刃按完整父子变换后的剑身扫掠方向校准，不能只根据世界 XYZ 或剑尖朝向认定刃口正确。80 FPS 原生采样中，五式主要发力段的刃口方向与横向扫掠方向夹角最大约 22°；握持中心位移误差为 0，长轴插值偏差最大约 0.19°。具体采样和几何检查见本次导出的 blade_alignment_report.json 与 blade_geometry_verification.json。

两个银色剑光标记仍直接跟随 `sword`，本地 pivot 保持原值。未来剑光与武器碰撞取点必须包含这次新增的剑骨骼动画，不能仍把 `sword` 当作静态骨骼。此修正已做模型回放与导出，运行时判伤和着色器仍待接入。

1. 登龙后进入拟拔刀蓄力，使用 `sword_trail_start` / `sword_trail_end` 的完整动画世界位置建立剑的轴线。银色 cube 正式隐藏，骨骼保留。
2. 初段为稀疏暖金细流从肩背周围和剑侧向剑身汇聚，中段增加连续光带，末段沿剑根到剑尖形成一条清楚的亮刃。不要用满屏随机粒子替代可见流动方向。
3. 初始颜色建议：外沿琥珀金 `#D99120`，主体亮金 `#FFC94A`，细核心淡金白 `#FFF3C4`。这是歼灭斩专用调色，不改白金普攻。
4. 剑在移动，汇聚端必须每帧随完整骑乘+始皇+手腕+剑变换更新；保持路径局部连续，不从上个世界位置拉出长光线。瞬移、中断、卸载、换动作时清空历史。
5. 斩击时由持续吸入切成沿刃爆发，先出现横斩弧，紧接同一事件扩展为全场冲击波；不能蓄力尚未完成就先放全场环。

### 全场金色冲击波

- 来源：`SLASH_RELEASE`，与承载点 `CENTER_REACHED` 同一拍，不加额外停顿。视觉从真实剑弧起始并迅速连接到以场地中央为中心的扩张波。
- 分层：薄而亮的金白前沿、较宽的半透明金色波面、稀疏外逸碎光。波面需覆盖地面玩家高度，表现为具有竖向厚度的冲击幕；不能只在高空龙背高度画一个平环。
- 范围：读取实际主战场边界，扩张至少覆盖最远角落并留视觉衰减边缘；不是写死一个仅覆盖圆内的小半径。保持建筑和玩家轮廓可读，避免用不透明金色圆盘遮满镜头。
- 节奏提案：横斩发生后约 0.8～1.0 秒覆盖全场，余光约 0.6 秒淡出；实际范围变化时仍保持全场可见的扫过过程。
- 惩罚一次结算：当前副本有效参战玩家每人一次，不因环线多层/分段重复受伤。无角落、跳跃或柱后安全区；伤害参数与防御交互待定。普通创造/旁观和已离开战斗者按项目既有参与者规则处理。
- 伤害时点与波前抵达一致的方案优先；显示用的薄环本身不是可被跳过的唯一碰撞判定。客户端粒子多少不得决定是否受到惩罚。
- 演出期间暂停巡飞落雷和其他组合技；结束后恢复巡飞与战斗。没有要求强制切镜头、冻结玩家或添加闪白屏，本轮不擅加。

### 墓龙显现与雷光

- 逐节出龙以完整骨骼姿态配合几何显隐/入口裁切制作，顺序为头、颈、身、尾；不缩放父骨骼为零来隐藏单段。显现入口位于始皇背后，入场后不一直跟随背部拖动巡飞龙。
- 雷光取点用真实左右角骨骼；粒子先向角尖聚合，再沿电弧下放。常态为同轮三道固定落雷，金合击另为沿剑路前中后三次落雷，不能混用。
- 不生成会烧毁建筑、留下随机火灾的原版雷击副作用；后续独立决定视觉实体与服务器判伤方式。
- 身体出现、绕场、召回、骑乘由共同动作时钟同步，客户端渲染与服务端位置不能各算一套不同龙身。骑乘区稳定不意味着全龙僵住，颈尾仍保留相位运动。
