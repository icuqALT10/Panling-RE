# 项目源码审查与优化记录

2026 年 9 月 30 日，对项目的 404 个 Java 源文件做了全量静态扫描，并重点阅读网络入口、制作菜单、数据匹配、技能调度、碰撞判定、存档更新及其调用链。检查了 604 个 JSON 和 mcmeta 文件。已实施 19 个生产源码文件的局部修改，修复可复现的物品消耗问题，并减少范围查询与提示匹配的重复工作。

全量扫描不等于逐行穷尽所有玩法组合。本次验证包含编译、打包和隔离的真实服务器 GameTest；没有进行客户端帧率基准或完整 Boss 战斗实测。项目原有未提交修改被保留，游戏存档和美术资源未被本轮操作修改。

## 已完成的修复与优化

| 问题 | 修改后的行为 | 主要源码 |
| --- | --- | --- |
| 炼丹炉和制符台的快捷制作循环扣过材料，结束时又调用输出槽的 `onTake`，可额外扣一次材料 | 每批产物只调用一次材料结算；背包无法继续接收时停止 | `world/inventory/ldlMenu.java`、`zftMenu.java` |
| 三种制作菜单在背包只能接收部分产物时可能覆盖剩余输出 | 已装入背包的部分保留，其余按原版工作台行为掉落给玩家 | 三个制作菜单 |
| 空配方、越界槽位和重复槽位仍可能匹配，造成无材料产物或扣料与匹配不一致 | 三类配方都拒绝这些输入，并检查输入槽数量 | `recipe/LdlRecipe.java`、`dztRecipe.java`、`zftRecipe.java` |
| 所有范围技能查询都向外扩大 128 格，再逐个排除无关实体 | 普通实体只查询实际作用区域；原生部位集合和主体集合继续补查大型生物 | `entity/MultipartEntity.java` |
| 多部位主体的静态弱引用集合被集成服务器两端共享，写入和迭代没有同步 | 写入使用同步集合，迭代持有同一把锁；已移除部位不再参与区域命中 | `entity/MultipartEntity.java` |
| Look Tip 对每次请求重复解析相同 SNBT，方块匹配还打印完整 NBT 调试信息 | 在数据重载时预解析 SNBT，一次发布不可变配置快照，匹配复用解析结果并取消高频调试输出 | `looktip/LookTipLoader.java`、`LookTipMatcher.java` |
| Look Tip 服务端在没有方块实体时忽略位置条件；非法资源名会触发异常 | 服务端与客户端复用基础条件检查，并直接校验实际方块坐标；非法资源名不匹配 | `looktip/LookTipMatcher.java` |
| Look Tip 服务端直接读取客户端给出的方块坐标，可加载远处区块 | 只处理世界边界内、已加载且位于玩家注视范围内的目标；非法目标类型返回 NONE | `looktip/LookTipNetworkHandler.java`、`LookTipRequestPayload.java` |
| Look Tip 每个渲染帧做射线与实体查询，并把方块状态转为字符串比较 | 每个游戏 tick 检查一次；直接比较方块状态，距离比较使用平方值 | `looktip/LookTipOverlay.java` |
| 远程客户端没有服务端 Look Tip 配置，无法从本地匹配触发请求 | 远程连接下，目标变化时请求服务器匹配；本地世界仍使用已加载条件；切换世界及本地数据重载后重置目标缓存 | `looktip/LookTipOverlay.java` |
| 火焰轨迹只按坐标索引，不同维度的相同坐标会串数据 | 使用维度和不可变坐标共同索引，保持原有 60 tick 时长 | `entity/FireTrailTracker.java`、`FireTornadoEntity.java` |
| 龙卷风保存了寿命和目标，但没保存自定义伤害 | 保存并恢复伤害；旧存档没有字段时保持原有默认值 15 | `entity/FireTornadoEntity.java` |
| 玩家跨维度离开局部天气时，收到的是 Boss 原维度的天气 | 恢复玩家当前所在维度的真实天气 | `util/LocalWeatherManager.java` |
| 延迟技能、震动波、施法、任务选择、狙击目标缓存在退出服务器后仍可能保留；部分玩家缓存在离线时没有释放 | 在服务器停止时清理；玩家离线时释放施法、任务选择和狙击目标缓存 | `event/GameBusEvents.java`、`skill/SkillCastManager.java`、`task/TaskGuideService.java`、`network/TianXingTargetPayload.java` |

源码路径均相对于 `src/main/java/icu/icuqalt10/panlingre/`。现有自定义配方的材料槽通过全量扫描，没有因新增校验而被拒绝。

## 验证结果

正常构建及现有世界模板回归测试通过：

```powershell
.\gradlew.bat build worldTemplateTest --offline --console=plain
```

新增 10 个 GameTest 通过。它们在 `build/source-review-run` 的独立世界中运行，不读取 `run/saves`：

```powershell
.\gradlew.bat -I scripts/source-review-tests.gradle runGameTestServer --offline --console=plain
```

测试覆盖三种制作菜单的单批材料消耗、部分背包容量和满背包；异常配方拒绝；普通方块的位置条件；火焰轨迹维度隔离、不可变坐标和过期；龙卷风伤害存档及旧格式兼容；远离主体的部位命中、OBB 外接盒空角与已移除部位；Look Tip SNBT 重载与实体条件变化；远端请求不会加载区块和非法目标类型。

最初 5 个测试中，4 个在修改前失败；相应缺陷修复后通过。后续扩展到 10 个。正常发布构建不加载该测试源集。

测试源码位于 `src/sourceReviewTest/`。构建和测试日志保存在 `build/reports/source-review/`。604 个资源文件均通过 JSON 语法检查。

## 后续优先事项

以下事项有源码证据，但涉及联机时序、玩法响应速度或渲染表现，适合单独验证后再修改。

1. **Look Tip 响应关联和持续刷新。** 当前响应只有文本，没有目标或请求编号。已丢弃看向空处时到达的响应，但快速切换两个目标时仍可能短暂显示上一个目标的结果；盯住同一实体期间，名字、位置或 NBT 变化也不一定触发重新匹配。建议加入请求编号并验证延迟、乱序目标切换和 `/reload`。远程客户端提示显示及本轮每 tick 检查的响应感，需要双端实测。
2. **副本预热的单次耗时。** `InstanceManager.tick()` 每 10 tick 取一个建造任务，但 `build()` 在主线程一次加载所需区块并放置完整模板。建议先记录每个模板的放置耗时；若观察到卡顿，再按区域分批处理，保持 READY 状态只在完整建造后出现。
3. **曲线拖尾的每帧分配。** `JinLiRenRenderer` 和 `ZhuRiArrowRenderer` 会生成采样点和环形顶点，并重复计算三角函数。建议在多投射物场景中测量分配和渲染耗时，再缓存固定圆周系数及稳定的曲线数据，验证宽度、渐变和消退效果。
4. **任务条件指令成本。** `TaskGuideService` 每 3 tick 对有任务的玩家执行条件指令。建议优先测量多玩家和复杂条件的成本，再考虑缓存命令解析结果；保留实际执行与条件副作用语义。
5. **八方仪配置读取。** 每次打开界面或传送时，`BaFangYiLoader.loadAll()` 都重新扫描并解析资源。若配置量增大，可改为随数据重载构建只读缓存；缓存需要随服务器关闭释放并随 `/reload` 更新。
6. **客户端跨服务器状态。** 技能冷却和部分视觉状态使用静态缓存。建议用连续进入两个不同服务器的场景检查冷却、施法动画、假雪和火焰轨迹是否残留，再在连接生命周期集中清理。

本次已移除范围查询中的固定 128 格扩圈，并把每帧提示匹配降为每 tick；这说明重复工作减少，不构成 FPS 或 TPS 提升比例的实测结论。Boss 骨骼、动画、美术资源和技能数值未进行整体重构。

回归使用了项目本地 NeoForge 21.1.224、GeckoLib 4.7.5.1 和 Java 21。测试启动方式参考 [NeoForge ModDevGradle 文档](https://docs.neoforged.net/toolchain/docs/plugins/mdg/)。
