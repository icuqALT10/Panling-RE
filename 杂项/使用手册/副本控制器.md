# 盘灵 RE 副本系统使用手册

本文档说明 `icu.icuqalt10.panlingre.instance` 模块的用途、配置格式、运行流程，以及如何接入一个新的单人副本。

## 1. 系统定位

该模块负责主世界中的多槽位单人副本，包括：

- 从资源包读取副本定义 JSON；
- 从原版结构模板 `.nbt` 生成场地；
- 启动服务器后预生成指定数量的槽位；
- 为玩家分配空闲槽位并传送；
- 每 tick 驱动对应的 Java 控制器；
- 检测玩家死亡、掉线、重新登录及越界；
- 执行数据包中的成功、失败函数；
- 副本结束后清理实体并重建场地。

当前系统只在主世界运行，暂不支持组队副本和其他维度。

通用框架与具体玩法严格分离：

- JSON 只保存所有副本共有的场地及调度信息；
- Java 控制器保存题目、怪物坐标、波次、Bossbar、音效等玩法细节；
- 数据包负责准入检查、任务推进、奖励和剧情指令。

## 3. 副本定义 JSON

文件放在：

```text
data/<命名空间>/instance/<路径>.json
```

例如：

```text
data/panlingre/instance/qinglong.json
```

对应副本 ID：

```text
panlingre:qinglong
```

当前青龙配置示例：

```json
{
  "controller": "panlingre:qinglong",
  "template": "panlingre:instance/qinglong",
  "center_pos": [0.0, 70.0, 2000.0],
  "player_spawn_pos": [0.5, 61.0, 2020.5],
  "spacing": 128,
  "prewarm_slots": 5,
  "arena_version": 1,
  "success": "plre:instances/qinglong/success",
  "failure": "plre:instances/qinglong/failure"
}
```

字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `controller` | 是 | Java 控制器注册 ID。每次创建会话时由注册表创建新的控制器对象。 |
| `template` | 是 | 原版结构模板 ID。 |
| `center_pos` | 是 | 槽位 0 的绝对中心坐标，同时用于结构居中和玩家越界检测。 |
| `player_spawn_pos` | 是 | 槽位 0 的玩家绝对出生坐标。 |
| `spacing` | 是 | 相邻槽位在 X 轴上的间隔，必须大于 0。 |
| `prewarm_slots` | 否 | 预生成及最大并发槽位数量，默认值为 5。 |
| `arena_version` | 否 | 场地版本，默认值为 1。修改 NBT 后应手动递增。 |
| `success` | 是 | 成功时以玩家身份执行的 mcfunction。 |
| `failure` | 否 | 失败时以玩家身份执行的 mcfunction。省略后失败时不调用函数。 |

不要把以下内容放入通用 JSON：

- 怪物生成坐标；
- 怪物 NBT；
- 题库及正确答案；
- Boss 技能参数；
- 音效和 BGM；
- 某一副本独有的倒计时或波次。

这些属于玩法控制器，应写在对应的 Java 类中。这样通用 JSON 不会随着玩法增加而不断膨胀。

## 4. 坐标和槽位算法

槽位沿 X 轴排列。槽位编号从 0 开始：

```text
slotCenter       = center_pos       + (slot × spacing, 0, 0)
slotPlayerSpawn  = player_spawn_pos + (slot × spacing, 0, 0)
```

控制器中的绝对坐标也应以槽位 0 为基准，再自行增加：

```java
double slotOffset = (double) session.slot() * session.definition().spacing();
Vec3 actualPos = basePos.add(slotOffset, 0.0, 0.0);
```

### 4.1 结构放置原点

`center_pos` 不是结构边角，而是结构几何中心。框架读取 NBT 的实际尺寸后计算放置原点：

```text
origin.axis = floor(center.axis - (templateSize.axis - 1) / 2)
```

因此结构会以 `center_pos` 为中心生成。修改 `center_pos` 会同时移动：

- 结构场地；
- 副本范围中心；
- 控制器通过 `session.center()` 获取的中心。

它不会自动移动控制器中硬编码的怪物绝对坐标；控制器坐标需要同步调整。

### 4.2 越界范围

玩家允许活动的范围是以 `session.center()` 为中心、半径为 `spacing / 2` 的三维球体：

```text
distanceSquared <= (spacing / 2)²
```

该判断包含 Y 轴。如果场地高度较大，应确保最高点和最低点仍在球体内。

`spacing` 还必须足以防止相邻结构、技能索敌、声音和粒子互相影响。

## 5. 结构模板

模板文件位置：

```text
data/<命名空间>/structure/<路径>.nbt
```

例如：

```text
data/panlingre/structure/instance/qinglong.nbt
```

对应模板 ID：

```text
panlingre:instance/qinglong
```

结构方块界面的单轴 48 格限制不等于 NBT 模板加载限制。框架直接通过 `StructureTemplateManager` 加载并放置模板。

场地重建前会执行以下操作：

1. 同步加载模板覆盖的全部区块；
2. 杀死模板包围盒内的玩家；
3. 对其他实体执行 `discard()`，避免正常死亡掉落；
4. 再次清除玩家死亡后可能产生的掉落物；
5. 放置完整结构模板；
6. 将槽位标记为 `READY`。

如果希望重建时删除玩家放置的方块，结构模板中必须包含相应的空气。需要保留、不覆盖的位置应使用 `structure_void`。

## 6. 槽位预热和场地版本

服务器启动后，框架读取全部副本定义，并检查前 `prewarm_slots` 个槽位。

槽位状态：

```text
PREPARING → READY → RUNNING → PREPARING
```

- `PREPARING`：等待生成或重建；
- `READY`：可以分配；
- `RUNNING`：正在被玩家使用。

生成请求放入队列，每隔 10 tick 最多放置一个场地，避免所有模板在同一 tick 生成。

生成记录保存在主世界的：

```text
data/panlingre_instances.dat
```

当存档中记录的版本等于 JSON 的 `arena_version` 时，启动时不会重复铺设该槽位。

修改模板后必须递增版本：

```json
"arena_version": 2
```

否则已有槽位仍会被视为最新版本。

副本开始时，该槽位的持久化版本会立即标记为 `-1`。如果服务器异常关闭，下次启动会自动重建，避免使用可能被污染的场地。

## 7. 启动副本

命令格式：

```mcfunction
plre instance start qinglong
```

也可以使用完整 ID：

```mcfunction
plre instance start panlingre:qinglong
```

命令只能由玩家执行。建议不要让玩家直接绕过剧情调用，而是在数据包检查函数中调用：

```mcfunction
# plre:instances/qinglong/check
execute unless <进入资格> run return fail

# 在启动前完成禁止传送、清除状态等操作
plre bafangyi off @s

plre instance start qinglong
```

进入前检查不属于 Mod 副本框架。`start` 只负责检查：

- 玩家是否已有活动会话；
- 副本定义是否存在；
- 是否有 `READY` 槽位；
- 控制器是否已经注册。

## 8. 会话生命周期

启动成功后，框架执行：

1. 占用最小编号的空闲槽位；
2. 将槽位持久化版本标记为脏；
3. 创建新的控制器对象和 `InstanceSession`；
4. 给玩家添加 `panlingre.instance.active` 标签；
5. 将玩家传送到该槽位的出生点；
6. 调用控制器的 `start(session)`；
7. 此后每个服务器 tick 调用 `tick(session)`。

玩家在以下情况失败：

- 控制器调用 `session.finish(InstanceResult.FAILURE)`；
- 玩家在副本中死亡；
- 玩家离开允许范围；
- 玩家退出服务器；
- 玩家带着遗留活动标签重新登录；
- 服务器停止时仍有活动会话。

越界和正常退出会直接杀死玩家。活动标签用于区分普通玩家和正在副本中的玩家，普通玩家退出不会被处罚。

结束时框架执行：

1. 防止同一会话重复结束；
2. 从活动会话表中移除玩家；
3. 调用控制器的 `stop(session, result)`；
4. 将槽位重新标记为 `PREPARING` 并排队重建；
5. 移除玩家的活动标签；
6. 成功时执行 `success`，失败时执行可选的 `failure`。

框架不会把玩家送回进入副本前的位置。传送目的地由 `success` 或 `failure` 函数自行决定。

## 9. 数据包回调

回调通过玩家的命令源执行：

- 执行者是该玩家；
- 命令权限等级临时提升到 2；
- 命令反馈被隐藏；
- 不需要在 JSON 中写 `function` 前缀。

JSON：

```json
"success": "plre:instances/qinglong/success",
"failure": "plre:instances/qinglong/failure"
```

对应文件：

```text
data/plre/function/instances/qinglong/success.mcfunction
data/plre/function/instances/qinglong/failure.mcfunction
```

成功函数示例：

```mcfunction
advancement grant @s only plre:misson/qinglong
plre bless @s add qinglong
plre bafangyi on @s
tp @s <成功后坐标>
```

失败函数可以省略。若保留，可用于恢复八方仪、清除效果或记录失败：

```mcfunction
plre bafangyi on @s
```

注意：玩家死亡触发 `failure` 时，函数运行在死亡流程中。不要假设玩家仍处于正常存活状态。

## 10. 编写新控制器

每种玩法实现一个 `InstanceController`：

```java
public final class ExampleController implements InstanceController {
    @Override
    public void start(InstanceSession session) {
        // 初始化 Bossbar、生成怪物、播放音乐等
    }

    @Override
    public void tick(InstanceSession session) {
        // 推进状态机；不要阻塞服务器线程
    }

    @Override
    public void onEntityDeath(InstanceSession session, LivingEntity entity) {
        // 处理由该会话登记的实体死亡
    }

    @Override
    public void stop(InstanceSession session, InstanceResult result) {
        // 移除 Bossbar、临时实体、客户端音乐等
    }
}
```

常用会话接口：

| 方法 | 含义 |
| --- | --- |
| `session.server()` | 当前服务器。 |
| `session.level()` | 主世界 `ServerLevel`。 |
| `session.player()` | 当前玩家；掉线后可能返回 `null`。 |
| `session.instanceId()` | 当前副本定义 ID。 |
| `session.definition()` | 当前副本通用配置。 |
| `session.slot()` | 分配到的槽位编号。 |
| `session.center()` | 已应用槽位 X 偏移的中心点。 |
| `session.playerSpawn()` | 已应用槽位 X 偏移的出生点。 |
| `session.finish(SUCCESS)` | 成功结束。 |
| `session.finish(FAILURE)` | 失败结束。 |

控制器应当是每个会话独立创建的对象。状态应保存为实例字段，不要使用静态可变字段，否则多个并行槽位会共享状态。

## 11. 注册控制器

在 `InstanceControllerRegistry` 中注册工厂：

```java
register(
        ResourceLocation.fromNamespaceAndPath("panlingre", "example"),
        ExampleController::new
);
```

然后在 JSON 中引用：

```json
"controller": "panlingre:example"
```

不要在 JSON 中填写 Java 类全名，也不要通过反射创建控制器。

## 12. 登记控制器实体

如果控制器需要接收某个实体的死亡事件，生成实体后必须登记：

```java
InstanceManager.ownEntity(session, entity);
```

框架收到 `LivingDeathEvent` 后，会把事件转交给对应会话：

```java
controller.onEntityDeath(session, entity);
```

主动丢弃实体前应解除登记：

```java
InstanceManager.releaseEntity(entity);
entity.discard();
```

副本结束时框架也会清除该会话的全部实体归属映射。

## 13. 青龙控制器示例

`QinglongController` 展示了一种基于状态机的实现：

- 进入后进行 5 秒准备倒计时；
- 20 道题随机且不重复；
- 每题生成四个骷髅，答案与位置重新随机匹配；
- Bossbar 标题显示问题，进度显示剩余时间；
- 答对 10 道成功，答错 3 道失败；
- 每次答题后等待 2 秒再刷新；
- 通关后等待 2 秒再调用 `success`；
- 题目刷新、答对、答错、通关分别播放音效。

青龙独有配置均保存在控制器中：

```java
private static final int START_COUNTDOWN_TICKS = 5 * 20;
private static final int QUESTION_TICKS = 20 * 20;
private static final int ANSWER_DELAY_TICKS = 2 * 20;
private static final int SUCCESS_DELAY_TICKS = 2 * 20;
private static final int REQUIRED_CORRECT = 10;
private static final int MAX_WRONG = 3;
```

四个骷髅坐标是槽位 0 的绝对坐标：

```java
private static final List<Vec3> BASE_ANSWER_POSITIONS = List.of(...);
```

生成时统一增加 `slot × spacing` 的 X 偏移。

骷髅属性集中在：

```java
private static final CompoundTag ANSWER_SKELETON_NBT = parseSkeletonNbt("{...}");
```

位置和翻译名称会在加载 SNBT 后覆盖，因此 SNBT 中不应配置 `Pos` 或最终 `CustomName`。

题目使用语言键：

```text
instance.panlingre.dragon.question1
instance.panlingre.dragon.answer1a
instance.panlingre.dragon.answer1b
instance.panlingre.dragon.answer1c
instance.panlingre.dragon.answer1d
```

正确答案保存在控制器的 `correct` 数组中，数字采用从 0 开始的索引：

```text
0 = A
1 = B
2 = C
3 = D
```

修改题目后必须同步检查题目数量、答案语言键和正确答案数组。

## 14. 青龙 BGM

四兽 BGM 资源：

```text
assets/panlingre/sounds/instance/sishou.ogg
```

声音事件在 `sounds.json` 中注册为：

```text
panlingre:instance.sishou
```

`QinglongMusicManager` 在客户端维护循环音乐：

- 0–5 秒：音量由 0% 增加到 50%；
- 5–7 秒：音量由 50% 增加到 100%；
- 正常播放阶段保持 100%；
- 收到停止消息后用 2 秒淡出；
- 客户端离开世界时立即停止。

服务端通过 `QinglongMusicPayload(true/false)` 控制开始和淡出。需要类似 BGM 的新控制器时，可以复用这一模式，但不要在服务端用多个 `playSound` 模拟淡入淡出。

## 15. 添加新副本的完整清单

1. 准备结构模板：

   ```text
   data/panlingre/structure/instance/example.nbt
   ```

2. 添加通用定义：

   ```text
   data/panlingre/instance/example.json
   ```

3. 创建 `ExampleController` 并实现 `InstanceController`。

4. 在 `InstanceControllerRegistry` 注册控制器工厂。

5. 将怪物坐标、NBT、音效等玩法细节写在控制器中。

6. 添加所需语言键、声音事件和网络包。

7. 在地图数据包中添加 `check`、`success`，以及可选的 `failure`。

8. 修改 NBT 后递增 `arena_version`。

9. 编译验证：

   ```powershell
   .\gradlew.bat compileJava processResources --no-daemon
   ```

10. 在测试存档中确认：

    - 5 个槽位是否依次生成；
    - 结构中心和出生点是否正确；
    - 相邻槽位是否互不干扰；
    - 成功、失败、死亡、越界、掉线是否正确清理；
    - BGM、Bossbar 和临时实体是否能正常停止。

## 16. 常见问题

### 命令提示“场地正在准备”

没有 `READY` 槽位。等待预热队列完成，并检查日志中是否存在模板缺失或放置失败。

### 修改 NBT 后建筑没有更新

递增对应 JSON 的 `arena_version`。否则存档中的已生成版本仍然有效。

### 场地生成位置偏移

确认填写的是结构几何中心而不是边角，同时检查 NBT 实际尺寸。偶数尺寸的几何中心可能位于两个方块之间，允许在 JSON 中使用 `.5` 坐标。

### 玩家刚进入就被判定越界

检查 `player_spawn_pos` 到 `center_pos` 的三维距离是否小于 `spacing / 2`，特别注意 Y 轴。

### 怪物死亡没有通知控制器

确认生成后调用了 `InstanceManager.ownEntity(session, entity)`，并且没有提前解除登记。

### 普通玩家退出是否会被处罚

不会。只有存在活动会话或带有 `panlingre.instance.active` 标签的玩家才进入副本退出惩罚流程。

### `/reload` 后定义何时生效

JSON 会随资源重载重新解析。为避免替换正在运行的定义，`InstanceManager` 只会在当前没有活动会话时重建运行时定义和预热队列。

### 为什么没有自动返回进入前的位置

这是有意设计，避免玩家在踏板或触发区域形成进入循环。成功后的传送应写在 `success`；失败后的处理写在可选的 `failure`。

## 17. 当前限制

- 仅支持主世界；
- 每个会话只有一个玩家；
- 槽位只沿 X 轴排列；
- 越界范围固定为 `spacing / 2` 的三维球体；
- `prewarm_slots` 同时决定预热数量和最大并发量；
- 尚无查询、强制结束、手动重建等管理员命令；
- 控制器注册仍需修改 Java 注册表并重新编译。

扩展框架时，应优先保持 JSON 简洁，只加入真正适用于所有副本的通用字段。
