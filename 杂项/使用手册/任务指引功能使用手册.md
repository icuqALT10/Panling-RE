# 任务指引功能使用手册

## 功能概述

任务指引用于帮助玩家寻找任务地点或目标实体，支持：

- 在屏幕右下角显示任务文本。
- 在目标地点方向显示路标和距离。
- 搜索并高亮附近符合条件的实体。
- 根据玩家状态，在多个候选条目中动态选择目标。
- 使用快捷键临时显示或隐藏方位路标。

每名玩家同一时间只能启用一个任务。启用新任务时，旧任务会被替换。

## 配置文件位置

任务配置放在：

```text
data/panlingre/task/
```

例如：

```text
data/panlingre/task/test.json
data/panlingre/task/location/middle/tie_jiang_pu.json
```

对应的指令路径为：

```text
test
location/middle/tie_jiang_pu
```

注意：

- 不填写 `.json`。
- 不填写 `data/panlingre/task/`。
- 不使用 `panlingre:test` 这样的命名空间格式。
- 文件应使用 UTF-8 编码。
- 修改配置后使用 `/reload` 重新加载。

## 指令

任务指令要求权限等级不低于 2，并且必须以玩家身份执行。

### 启用任务

```mcfunction
/plre task guide on <任务路径>
```

例如：

```mcfunction
/plre task guide on test
/plre task guide on location/middle/tie_jiang_pu
```

启用新任务会替换玩家当前的任务。

### 关闭任务

```mcfunction
/plre task guide off
```

这会关闭当前玩家的任务文本、路标、实体高亮和服务端任务状态。即使原本没有启用任务，也会返回 `1`。

### 查询任务

```mcfunction
/plre task guide query <任务路径>
```

当前启用的正是该任务时返回 `1`，否则返回 `0`。

### 在命令方块或函数中使用

必须提供玩家执行上下文：

```mcfunction
execute as @a at @s run plre task guide on test
execute as @a at @s run plre task guide off
```

## 顶层格式

```json
{
    "title": {
        "text": "任务文本"
    },
    "entries": [
        {
            "target": {
                "pos": {
                    "x": 120,
                    "y": 64,
                    "z": 245
                }
            }
        }
    ]
}
```

顶层包含两个必填字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 文本组件 | 在屏幕右下角显示的任务文本 |
| `entries` | 列表 | 按顺序判断的任务目标条目，不能为空 |

不再使用顶层 `type`。每个条目是否启用路标或实体高亮，直接由该条目是否包含 `target`、`entity` 决定。

旧配置中暂时保留 `type` 不会影响读取，但建议删除。

## entries：有序条件条目

```json
"entries": [
    {
        "command": "execute if entity @s[tag=stage_2]",
        "entity": {
            "type": "minecraft:villager"
        },
        "target": {
            "pos": {
                "x": 200,
                "y": 64,
                "z": 300
            }
        }
    },
    {
        "target": {
            "pos": {
                "x": 120,
                "y": 64,
                "z": 245
            }
        }
    }
]
```

系统每次从第一条开始判断：

1. 没有 `command` 的条目无条件可执行。
2. 存在 `command` 时，指令返回值大于 `0` 才可执行。
3. 找到第一条可执行条目后立即停止，不再检查后续条目。
4. 只使用选中条目内的 `entity` 和 `target`。
5. 所有条目都不可执行时，任务仍保持开启并显示标题，但不显示路标或实体高亮。

无条件条目通常应放在最后，作为默认或兜底目标。

### 条目内容与渲染规则

`entity` 和 `target` 都是可选字段，并且互不依赖：

| 条目内容 | 实际效果 |
|---|---|
| 只有 `target` | 只显示地点路标 |
| 只有 `entity` | 只搜索并高亮实体 |
| 同时包含两者 | 同时显示路标并高亮实体 |
| 两者都没有 | 跳过两项功能，只保留任务标题 |

因此，不同条件条目可以使用不同的指引方式。例如，第一阶段寻找 NPC，第二阶段只前往一个地点，不需要再通过顶层类型保持一致。

### command（可选）

`command` 是一条不带 `/` 的 Minecraft 指令：

```json
"command": "execute if score @s quest_stage matches 2"
```

规则：

- 不填写时，条目始终可执行。
- 填写时不能为空。
- 不能以 `/` 开头。
- 返回值大于 `0` 视为条件成立。
- 返回值等于 `0` 或执行失败视为条件不成立。
- 以当前玩家作为 `@s` 执行。
- 执行权限等级为 4。
- 指令输出会被静默。

建议只使用没有副作用的状态判断，例如：

```json
"command": "execute if entity @s[tag=quest_started]"
```

```json
"command": "execute if score @s quest_stage matches 2"
```

不要使用 `give`、`summon`、修改分数等会产生持续副作用的指令，因为条件每 3 tick 可能执行一次。

### off_when_located（可选）

`off_when_located` 是布尔值，默认为 `false`：

```json
"off_when_located": true
```

设为 `true` 后，只要该条目是当前第一条可执行条目，并满足以下任意条件，系统就会直接关闭玩家的整个任务：

- 玩家距离 `target` 目的地不超过 3 格。
- 玩家距离任意符合该条目 `entity` 条件的实体不超过 2 格。

关闭会清除服务端保存的当前任务，并同步移除客户端的标题、路标和实体高亮。此后使用 `guide query` 查询该任务会返回 `0`。

距离和实体条件由服务端每 3 tick 验证。条目没有 `target` 时跳过地点判定，没有 `entity` 时跳过实体判定；两项都没有时不会自动关闭。

### 刷新机制

- 启用任务时立即判断一次。
- 玩家登录并恢复任务时立即判断一次。
- 此后服务端每 3 tick 重新判断。
- 始终按列表顺序短路，找到第一条可执行条目便停止。
- 只有选中条目的序号或 JSON 内容发生变化时才同步客户端。
- 条件没有变化时，不会每 3 tick 发送网络包。

## title：任务文本

`title` 是 Minecraft 文本组件。

普通文本：

```json
"title": "前往村庄寻找铁匠"
```

带样式：

```json
"title": {
    "text": "前往村庄寻找铁匠",
    "color": "gold",
    "bold": true
}
```

换行：

```json
"title": {
    "text": "任务指引\n前往村庄寻找铁匠",
    "color": "white"
}
```

翻译键：

```json
"title": {
    "translate": "task.panlingre.find_blacksmith"
}
```

任务文本显示在右下角，并自动追加一行较小的路标快捷键提示。

## target：地点路标

包含 `target` 时，当前条目会显示地点路标：

```json
"target": {
    "pos": {
        "x": 120,
        "y": 64,
        "z": 245
    }
}
```

规则：

- `x`、`y`、`z` 都必须填写，并且是整数。
- 玩家距离目标不超过 9999 格时显示。
- 距离小于 3 格时隐藏。
- 路标大小固定，不随距离变化。
- 屏幕外的目标会显示在屏幕边缘。
- 目标位于玩家背后时，路标会移动至屏幕下方。
- 路标下方显示三维直线距离。

### 路标快捷键

默认按 `J` 开启或关闭当前任务的指引内容。关闭时会：

- 隐藏 `target` 路标。
- 清除当前任务产生的实体高亮。
- 暂停 `entity` 搜索及相关网络发包。

任务标题、右下角快捷键提示和服务端任务状态不会关闭。重新开启后，路标会立即恢复，实体搜索会在下一次客户端 tick 恢复。

按键可在 Minecraft 按键设置中修改，右下角提示会显示实际绑定的按键。当前条目既没有 `target` 也没有 `entity` 时，按键不会执行切换。

## entity：实体条件

包含 `entity` 时，当前条目会搜索并高亮符合条件的实体。

### type（必填）

这里的 `type` 是 `entity` 内部的实体类型字段，与已经移除的顶层任务 `type` 无关。

单个实体 ID：

```json
"type": "minecraft:villager"
```

多个实体 ID：

```json
"type": [
    "minecraft:villager",
    "minecraft:wandering_trader"
]
```

实体 ID 必须包含命名空间。

### pos（可选）

限制实体所在坐标。`x`、`y`、`z` 必须同时存在，每个轴可以是整数或闭区间：

```json
"pos": {
    "x": {
        "min": 110,
        "max": 130
    },
    "y": {
        "min": 60,
        "max": 80
    },
    "z": 245
}
```

范围规则：

- `min` 和 `max` 必须同时存在。
- 两端都包含在范围内。
- `min` 不能大于 `max`。

### nbt（可选）

使用 SNBT 字符串进一步匹配实体：

```json
"nbt": "{Tags:[\"quest_blacksmith\"]}"
```

实体实际 NBT 只要包含要求的内容即可。NBT 在服务端检查，SNBT 中的双引号需要在 JSON 内转义。

### color（可选）

设置实体高亮颜色：

```json
"color": "#E8C96A"
```

支持 `#RRGGBB` 和 `RRGGBB`。不填写时使用默认淡金色 `#E8C96A`。

## 实体搜索流程

选中的条目包含 `entity` 时：

1. 客户端每 5 tick 搜索玩家 50 格内已经加载的实体。
2. 客户端按实体类型、距离和坐标进行初筛。
3. 当前条目没有 `nbt` 时，客户端直接高亮初筛结果，不发送网络包。
4. 当前条目存在 `nbt` 时，候选实体 ID 才会合并进一个网络包，最多 128 个。
5. 服务端确认客户端仍在使用同一任务和同一条目。
6. 服务端重新验证距离、类型、坐标和 NBT。
7. 匹配结果只发送给对应玩家。
8. 客户端使用配置颜色渲染实体轮廓。

当前条目没有 `entity` 时，会跳过搜索和发包，并清除该任务先前产生的实体高亮。

实体高亮仅对当前玩家可见，不会修改服务端实体的发光状态。只有实际需要读取服务端 NBT 时才产生实体检查网络包。

## 完整示例

下面的任务第一阶段同时指向 NPC 和地点，第二阶段只显示地点路标：

```json
{
    "title": {
        "text": "任务指引\n寻找铁匠",
        "color": "white"
    },
    "entries": [
        {
            "command": "execute if score @s quest_stage matches 1",
            "entity": {
                "type": "minecraft:villager",
                "nbt": "{Tags:[\"quest_blacksmith\"]}",
                "pos": {
                    "x": {
                        "min": 110,
                        "max": 130
                    },
                    "y": {
                        "min": 60,
                        "max": 80
                    },
                    "z": 245
                },
                "color": "#E8C96A"
            },
            "target": {
                "pos": {
                    "x": 120,
                    "y": 64,
                    "z": 245
                }
            }
        },
        {
            "command": "execute if score @s quest_stage matches 2",
            "off_when_located": true,
            "target": {
                "pos": {
                    "x": 3162,
                    "y": 145,
                    "z": 106
                }
            }
        }
    ]
}
```

行为：

1. `quest_stage` 为 `1` 时，使用第一条，同时显示地点路标并高亮目标村民。
2. `quest_stage` 为 `2` 时，使用第二条，只显示地点路标，不进行实体搜索。
3. 其他阶段没有可执行条目，只显示任务标题。

## 状态保存

当前任务 ID 保存在玩家 Attachment 中：

- 死亡后保留。
- 退出并重新进入后保留。
- 服务端重启后保留。
- 登录时重新判断条目并同步客户端。

`J` 键控制的指引显示状态只属于本次客户端会话。重新启用其他任务或重新进入世界后，路标和实体高亮默认启用。

## 注意事项

1. `title` 和 `entries` 是顶层必填字段。
2. `entries` 不能为空，条目顺序会直接影响结果。
3. 顶层不再使用 `type`。
4. `entity` 和 `target` 都是条目内的可选字段。
5. 没有 `command` 的条目始终成立，通常只放在最后。
6. 条件指令不能带 `/`，并应避免任何副作用。
7. 配置没有维度字段，坐标按玩家当前维度解释。
8. 实体只有在玩家 50 格内且区块已经加载时才可能被发现。
9. `off_when_located` 默认为 `false`；设为 `true` 后，到达目标会直接关闭整个任务。
10. JSON 不支持注释。
